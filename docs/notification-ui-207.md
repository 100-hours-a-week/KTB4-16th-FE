# 알림 화면 및 진입 (#207)

## 변경 범위

| 기존                               | 변경                                                                  |
| ---------------------------------- | --------------------------------------------------------------------- |
| 홈 상단에는 로고와 날씨만 있다.    | 날씨 옆 알림 버튼에서 `/notifications`로 이동한다.                    |
| 알림 목록 라우트가 없다.           | 로그인 보호 라우트에서 알림 목록·빈 상태·오류·추가 페이지를 표시한다. |
| 친구 요청 알림의 이동 대상이 없다. | `/friends?tab=received`로 이동하고 받은 요청 탭을 연다.               |

친구 요청 입력을 검색으로 바꾸는 프론트 변경은 별도 작업으로 남긴다. 이 PR에서는 기존 친구 요청 입력 화면을 유지한다.

## 2026-10-12 화면 수정

| 이전 구현                                          | 이번 수정                                                                |
| -------------------------------------------------- | ------------------------------------------------------------------------ |
| 홈 알림 버튼에 미읽음 표시가 없다.                 | 미읽음 알림이 있으면 벨에 점을 표시한다.                                 |
| 읽음 저장 직후 알림 강조가 사라진다.               | 처음 연 알림은 이번 방문 동안 강조하고, 재방문하면 읽음 상태로 표시한다. |
| 받은·보낸 요청 버튼이 이름 바로 뒤에 놓일 수 있다. | 두 요청 목록의 버튼을 카드 오른쪽에 정렬한다.                            |
| 알림 목록에서 개별 알림을 지울 수 없다.            | 카드 오른쪽 삭제 버튼과 별도 확인 창으로 한 건씩 삭제한다.               |

## API와 표시 정책

계약 근거: 백엔드 `specs/openapi/MULO_OpenAPI_v2.8.yaml`의 `GET /api/notifications`, `PATCH /api/notifications/read`, `DELETE /api/notifications/{notificationId}`와 프론트 `docs/api-integration.md`의 인증·CSRF 규칙.

- 기존 인증 클라이언트로 `GET /api/notifications?size=20`을 호출한다. 다음 페이지는 서버 cursor를 `URLSearchParams`로 인코딩한다.
- 화면에서 조회한 미읽음 ID만 PATCH 본문에 담고 기존 CSRF 처리를 적용한다. GET 자체는 읽음 상태를 변경하지 않는다.
- 읽음 저장에 실패해도 목록을 유지하고 사용자에게 재시도 버튼을 제공한다. 서버에는 화면 진입 시 읽음을 저장하지만, 이번 방문에서 새로 연 항목의 강조는 다른 화면으로 이동할 때까지 유지한다. 재방문 시 서버의 `readAt`으로 읽음 상태를 표시한다.
- 홈의 미읽음 점은 기존 목록 API를 읽기 전용으로 호출해 확인한다. 필요한 경우 다음 cursor를 조회하며, 홈 진입·창 포커스·탭 재표시와 화면이 보이는 동안 1분 간격으로 갱신한다. 개수는 표시하지 않는다.
- offset 없는 서버 `LocalDateTime`은 KST로 해석하고, offset이 있으면 보존한다.
- 친구 요청은 `/friends?tab=received`, 친구 수락은 `/friends`, 월간 리포트는 `/report`로 이동한다. 채팅 화면이 아직 없거나 대상 ID가 null인 알림은 이동 링크를 표시하지 않는다.
- 알림 삭제 버튼은 목록을 밀지 않는 별도 확인 창을 연다. 취소·Escape로 닫고, 삭제 실패 시 창 안에서 재시도할 수 있다. 확인 후 본인 알림 한 건만 DELETE하며 성공 응답 이후 목록에서 제거한다. 삭제는 연결된 친구 요청·리포트 등 원본 자원을 변경하지 않는다.
- 미읽음 개수 배지는 이 화면 범위에 포함하지 않는다.

## 검증

`npm test -- --run`, `npm run prettier`, `npm run lint`, `npm run typecheck`, `npm run build`를 실행한다. 알림 cursor·읽음 처리·오류 복구·홈 진입·친구 요청 탭 이동을 확인한다.

의존성, 공용 API 클라이언트, 인증·토큰 저장 방식, 환경변수, DB/Flyway는 변경하지 않는다.
