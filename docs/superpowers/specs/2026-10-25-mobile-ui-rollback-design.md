# 디자인 유지·모바일 배치 통일 설계

**범위 변경:** 2026-10-25 사용자가 전체 원복을 취소하고 “디자인은 유지하고 반응형이였던 부분만” 되돌리도록 변경했다. 이어 상세도 모바일 1열로 배치하고 폰트·색상·카드 스타일을 유지한다고 확인했다. 이전 #131 → #130 전체 revert 절차는 실행하지 않는다.

## 목표와 경계

현재 모바일 기본 디자인을 유지하면서 태블릿·PC 너비에서 앱을 넓히고 재배치하는 규칙을 제거한다. 좁은 화면에서는 가로 폭을 채우고 큰 창에서는 모바일 프레임을 중앙에 둔다.

- 최대 폭은 이전 모바일 프레임의 480px을 적용한다. 새 600/840/1440px 확장 단계는 사용하지 않는다.
- 현재 `100dvh` 높이, 본문 내부 스크롤, safe-area, 긴 문자열 줄바꿈·overflow 방어를 유지한다. 옛 800px 높이 상한·바깥 여백까지 복구하는 작업은 아니다.
- 유지하는 디자인은 현재 모바일 기본 규칙의 고딕 글꼴, 색상 변수, 글자 크기, 간격, 버튼 크기, 테두리·둥글기·그림자다. PC 전용 글자 확대·바깥 여백은 확장 규칙과 함께 제거한다.
- 기존 API·인증·데이터 흐름·의존성·환경변수·CI/CD 설정은 바꾸지 않는다.

## 구현 판단

- PR #130/#131 이전부터 있던 장르 온보딩의 481px 중앙 대화상자 전환과 사진의 72vw/최대 420px 높이는 유지했다. 이번 대상은 앱의 PC 확장 배치이며 독립 대화상자·사진 크기를 새로 설계하지 않는다.

## 방법과 검증

최신 develop에서 별도 작업 브랜치/worktree를 준비해 확장 관련 CSS·JSX·JS 조건만 수정한다. 전체 merge revert·옛 파일 덮어쓰기는 디자인과 동작 보완을 함께 없애므로 사용하지 않는다. 최상위 폭 제한만 덧씌우는 방식도 내부 PC 규칙이 계속 적용되므로 사용하지 않는다.

`max-width`는 요소의 폭 상한이며 media query의 `width`는 viewport 폭을 검사한다. 따라서 480px 프레임을 1440px 창에서 볼 때도 기존 PC 미디어 규칙이 적용된다. 부모와 자식의 확장 규칙을 함께 정리하는 근거다. [MDN max-width](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/max-width), [MDN width media feature](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/width).

320/390/480/600/767/768/1023/1024/1440px에서 프레임 폭·메뉴 위치·본문 스크롤·시트·상세를 확인한다. `prefers-reduced-motion`, 360px 이하 좁은 화면 방어, 안전 영역 처리는 유지한다. “모든 media query 삭제”는 목표가 아니다.

제품 코드 수정과 로컬 검증을 완료했다. 전체 97파일·719테스트, prettier/lint/typecheck/build와 가상 데이터 기반 CSS viewport 검증이 통과했다. 상세 결과는 [실행 보고서](../reports/2026-10-25-mobile-layout-only.md)에 기록했다. 기존 전체 역패치의 264파일 동일성 검증은 이번 부분 수정의 증거로 재사용하지 않는다. 개발서버 배포는 수행하지 않았으며 사람이 PR을 병합한 이후 별도로 확인한다.

## 완료 기준

모바일 배치와 보존 디자인을 로컬에서 검증하고 PR 검사·사람의 리뷰/병합을 거친다. 이후 새 개발 이미지와 실제 VM 실행 tag/digest·개발 도메인 화면까지 확인한 뒤 개발서버 반영 완료로 보고한다. 개발서버만 대상이며 main/prod 변경은 포함하지 않는다.
