# MULO PC 확장형 반응형 화면 설계

- 작성일: 2026-10-24
- 기준 커밋: `f297da5` (`develop`)
- 상태: 구현·자동 검사·코드 리뷰 완료. 실제 연결·기기 확인 범위는 아래 검증 결과 참조.

## 1. 의도와 결정 사항

사용자는 화면이 어색해 보이는 핵심을 색상보다 웹·모바일의 크기, 픽셀 정렬, 간격의 불일치로 설명했다. PC에서도 480px 모바일 프레임을 유지하는 안과 PC 공간을 넓게 쓰는 안 중 **넓은 PC형**을 선택했다.

아래 폭·전환점·간격 수치는 이 선택을 구체화한 설계 제안이다. 사용자가 개별 수치를 지정한 것은 아니다. 기존 라벤더·민트·피치 색상과 음악·장소 중심의 서비스 정체성을 기준으로 삼는다.

제목과 본문은 전역 `--mulo-font-sans`를 사용하고 개별 제목은 원격의 `inherit` 설정을 통해 같은 고딕 계열을 상속한다. Pretendard와 한글 시스템 고딕 대체 글꼴을 사용하며 외부 폰트 요청이나 패키지를 추가하지 않는다.

## 2. 접근 비교

| 접근                           | 장점                                                     | 비용·제약                                          | 결정                        |
| ------------------------------ | -------------------------------------------------------- | -------------------------------------------------- | --------------------------- |
| PC에도 480px 앱 프레임         | 현재 배치와 검증 범위가 작음                             | 지도와 목록을 동시에 보기 어려움                   | 사용자가 PC 확장형 선택     |
| 기존 페이지 셸을 PC형으로 확장 | 넓은 지도와 정보 패널, 기존 페이지 상태·모달 소유권 유지 | 페이지별 셸 예외를 명시적으로 처리                 | 채택하는 구현 방향          |
| 라우터 위에 새 전역 셸 추가    | 모든 화면의 외곽을 한곳에서 조립                         | 인증·중첩 상세·인라인 채팅·모달 차단 범위까지 변경 | 이번 범위에서 사용하지 않음 |

기존 `pages -> features -> entities -> shared` 의존 방향과 현재 React·TypeScript·CSS를 사용한다. 새 UI 라이브러리를 추가하지 않는다.

## 3. 화면 크기 기준

비교 단위는 브라우저의 CSS px이다. 같은 레이아웃을 확대·축소하는 대신 사용 가능한 공간에 따라 배치를 바꾼다.

| 구간                           | 바깥 프레임                             | 주요 메뉴                         | 홈의 본문                                     |
| ------------------------------ | --------------------------------------- | --------------------------------- | --------------------------------------------- |
| 모바일: 320–767px              | 전체 폭·최대 600px 중앙 정렬, 가시 높이 | 기존 하단 메뉴                    | 검색·추천 진입·지도, 선택 목록은 바텀시트     |
| 태블릿: 768px 이상·1024px 미만 | 좌우 최소 16px, 최대 840px 중앙 정렬    | 기존 메뉴를 상단 가로 메뉴로 표시 | 추천 진입 2열, 전체 폭 지도, 선택 목록은 시트 |
| PC: 1024px 이상                | 좌우 24px, 최대 1440px                  | 왼쪽 184px 세로 메뉴              | 넓은 지도 + 오른쪽 288–320px 정보 패널        |

- PC 프레임은 최대 높이 800px 제한을 없앤다. 화면 높이에서 상하 여백 48px을 제외하고, 본문·목록을 각각 필요한 영역 안에서 스크롤한다.
- 태블릿은 상하 16px을 제외한 가용 높이를 사용한다. 모바일은 동적 뷰포트와 기기 안전 영역을 반영한다.
- 태블릿 홈의 추천 진입 두 개를 한 줄에 배치한다. 모바일·태블릿 지도는 폭:높이 16:10을 기준으로 확보하고 남는 높이를 채운다. 최소 높이는 모바일 220px·태블릿 360px이다. 낮은 창에서는 지도를 압축하지 않고 본문을 스크롤해 생성 버튼까지 접근한다. 이 비율은 사용자의 지도 높이 피드백을 반영한 프로젝트 선택이다. 넓은 모바일에서 높이를 별도 전환하는 대신 비율을 계속 적용해 폭 변화에 따라 자연스럽게 늘어나도록 한다.
- 후속 가로 폭 피드백: 사용자는 지도와 앱 전체가 모두 길다고 확인했다. 셸 최대 폭 제한을 채택해 메뉴·검색·카드·지도를 같은 시작선에 두며, 600/840px은 구현자의 조정값이다. 지도만 제한하는 방식은 주변 요소와 폭이 달라지고, PC 배치를 더 이르게 전환하면 작은 지도에 사이드바까지 추가되므로 채택하지 않는다. 독립 채팅도 같은 구간을 따르고 인라인 채팅은 부모 폭을 사용한다. 인증 카드는 모바일에서만 최대 600px이며 태블릿·PC의 기존 420px 읽기 폭을 유지한다. `max-width`는 가용 폭 안에서 요소의 최대 폭을 제한한다. [MDN max-width](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/max-width)
- 1024–1199px에서는 오른쪽 패널 288px, 1200px 이상에서는 320px을 기준으로 한다. PC 최소 폭에서 지도에 약 420px을 남긴다.
- 481px에서 갑자기 PC 여백이 붙는 기존 분기를 위 구간으로 교체한다.
- 스크롤바 공간 예약은 모달 전후 이동 방지 목적을 보존하되, 모바일 폭을 불필요하게 줄이지 않도록 구간·브라우저별 계산 폭을 검증한다.
- 높이가 작은 창, 브라우저 확대, 긴 문자열에서도 문서·본문·시트가 중복 스크롤하거나 조작 요소를 덮지 않아야 한다. 데스크톱 창을 줄여도 주요 메뉴와 닫기 버튼에 접근할 수 있어야 한다.

## 4. 홈 배치와 동작

### PC

```text
┌──────────┬──────────────────────────────────────────┐
│ MULO     │ 기억 검색                         날씨·알림 │
│          ├───────────────────────────┬──────────────┤
│ 홈       │ 인기 자물쇠 / 내 자물쇠     │ 추천·랜덤 채팅 │
│ 대시보드 │                           │ 진입          │
│ 리포트   │       카카오 지도          │              │
│ 친구     │                           │ 자물쇠 만들기  │
│ 마이페이지│                           │              │
└──────────┴───────────────────────────┴──────────────┘
```

- 지도는 본문의 남는 폭과 높이를 사용한다. 메인 메뉴·검색·지도·정보 패널의 시작선과 바깥 여백을 일치시킨다.
- 오른쪽 패널은 기본 상태에서 기존 추천·랜덤 채팅 진입과 자물쇠 생성 행동을 제공한다. 지도에서 장소를 선택하면 같은 패널을 인기 음악 또는 내 자물쇠 목록으로 전환한다. 목록을 닫으면 기본 상태로 돌아간다.
- 기본 패널과 선택 목록을 별도 열로 동시에 추가하지 않는다. 작은 PC에서 지도가 좁아지는 것을 막기 위해 오른쪽 정보 영역은 하나만 둔다.
- 목록의 데이터·요청·선택 상태는 `HomeMap`에 유지한다. `HomePage`가 소유하는 추천 진입·페이지 이동 UI는 표현용 슬롯 또는 콜백으로 조립하며, API 로직을 페이지로 옮기지 않는다. 구체적인 슬롯 이름과 작은 표현용 컴포넌트 분리는 구현자가 정한다.
- 선택 목록의 PC 도크와 모바일 시트는 동일한 선택 상태와 요청 결과를 사용한다. 숨겨진 두 사본에서 요청하거나 서로 다른 선택 상태를 갖지 않는다.

### 모바일·태블릿

- 모바일의 검색 → 추천 진입 → 지도 → 자물쇠 생성 → 하단 메뉴 흐름을 유지한다.
- 태블릿은 가로 메뉴를 위에 두고 나머지 기능 순서와 목록 시트 동작을 유지한다.
- 크기 구간이 바뀌어도 선택 장소·입력·추천 세션을 레이아웃 변경만으로 초기화하지 않는다.

### 지도와 모달의 계약

- `window` 크기 변경 외에 패널 변경으로 지도 컨테이너 크기가 달라지면 지도 레이아웃을 재계산한다. 필요할 때 현재 중심을 보존하며, 불필요한 지도 재생성과 위치 권한 재요청은 하지 않는다.
- 레이아웃 재계산으로 발생한 `idle` 이벤트가 사용자 선택 목록을 즉시 닫지 않도록 검증한다. 사용자가 실제로 지도를 이동했을 때의 기존 갱신 정책과 구분한다.
- PC에서도 목록 닫힘 완료를 반드시 통지한다. `transform` 애니메이션을 없애거나 모션 감소 설정이 적용되어도 추천창 전환이 대기 상태에 남지 않아야 한다.
- 추천은 페이지 수준 모달로 유지한다. PC에서는 폭 최대 520px의 중앙 대화상자, 모바일·태블릿에서는 내용 높이에 맞춰 최대 70dvh까지 확장하는 바텀시트로 표시한다. 배경은 왼쪽 메뉴를 포함한 현재 페이지 전체를 차단한다.
- 추천 성공 최대 3회, 누적 제외 곡, 닫기 확인, 취소 응답 무시, 재진입 초기화, 초점 순환·복원은 유지한다. 추천 진입이 단순 패널 전환으로 바뀌어 세션이 계속 살아 있지 않도록 한다.

## 6. 메뉴·셀 구조

- 기존 `MainNavigation` 링크·아이콘·URL 활성 판별을 사용하며 메뉴 데이터를 복제하지 않는다.
- 이미 메뉴가 있는 페이지는 자신의 메뉴와 `inert` 소유권을 유지한 채 CSS 배치를 바꾼다. 라우터 위로 메뉴를 이동하지 않는다.
- 기억 검색·독립 상세·계정 수정처럼 메뉴가 없던 화면은 PC·태블릿에 한해 같은 메뉴를 조립한다. 모바일의 뒤로 가기 중심 흐름은 유지한다.
- 중첩된 자물쇠 상세와 인라인 채팅에는 부모 메뉴를 중복 생성하지 않는다. 독립 채팅은 기존 뒤로 가기 중심 화면을 유지한다.
- 작성 화면처럼 헤더가 본문 바깥 형제인 경우 전용 배치 영역 또는 표현용 wrapper를 명시해 헤더가 독립 열로 밀리지 않도록 한다.
- 시각적 메뉴 위치와 키보드 이동 순서를 함께 점검하고 중복 랜드마크·숨겨진 포커스 대상을 만들지 않는다.

## 7. 픽셀·타이포·컴포넌트 기준

아래 수치는 디자인 표준의 강제값이 아닌 이 작업의 제안값이다. 실제 긴 제목·작은 화면·확대 상태를 확인하면서 조정할 수 있다.

| 역할                | 기존 예                      | 제안 기준                                                          |
| ------------------- | ---------------------------- | ------------------------------------------------------------------ |
| 페이지 제목         | 공통 16px, 친구 26px         | 모바일 20px, PC 24px; 브랜드 로고는 별도                           |
| 본문·버튼           | 11–14px가 혼재               | 본문 14–16px, 주요 버튼 14–16px                                    |
| 보조 설명·메뉴 라벨 | 일부 9.5–11px                | 기본 12px                                                          |
| 화면 외곽·섹션      | 18·20·22px가 혼재            | 구간별 화면 여백, 섹션 24px, 카드 안쪽 16px을 기본으로 역할별 정의 |
| 카드·버튼 둥글기    | 역할에 따라 12·13·14·15·20px | 카드 20px, 버튼 12px, 상태 칩은 pill 형태                          |

반복 색상·간격·크기는 앱 전역 스타일 진입점에 CSS 변수로 정의한다. 홈 CSS의 전역 `:root`에만 있는 색상 토큰은 앱 초기 스타일로 옮겨 소유 위치를 맞춘다. `shared`에 페이지 조립 책임이나 새 디자인 시스템 라이브러리를 추가하지 않는다.

## 9. 검증·완료 조건

- CSS 폭 320, 360, 390, 767, 768, 1023, 1024, 1280, 1440에서 가로 넘침과 기준선 확인.
- 높이 640, 768, 900 및 200% 확대에서 메뉴·버튼·닫기 동작에 접근 가능.
- PC의 지도·오른쪽 패널 합이 본문 폭을 넘지 않으며 두 번째 도크가 생기지 않음.
- 모바일·PC 전환 중 선택·입력·추천 상태 유지, 지도 렌더링·중심·마커 동작 확인.
- 위치 미허용·지도 실패·빈 목록·긴 곡명에서도 레이아웃과 오류 안내 유지.
- 추천창·친구 대화상자의 배경 차단, Escape, 닫기 확인, 초점 복원 확인.
- 기존 관련 Vitest 테스트와 필요한 동작 회귀 테스트, prettier·lint·typecheck·build 수행. 순수 CSS 수치만 재검사하는 형식적인 단위 테스트는 추가하지 않음.
- 실제 기기의 주소창·소프트 키보드·안전 영역 검증을 브라우저 뷰포트 조절과 구분해 보고.
- 제품 메서드·Hook·새 표현용 컴포넌트에 짧은 책임 주석 작성. 완료 보고는 실제 파일·줄번호, 원본/변경 내용, 실행한 검증을 포함.
